els — Manual

A minimal, fast, single-file text editor for Windows. This manual covers version 0.97.

Overview

els is a clean editor for everyday text files: multi-file tabs, find & replace with real regular expressions, word wrap, recent files, session restore, and character-set auto-detection — shipped as a single self-contained els.exe with no installer and no dependencies beyond Windows itself.

Its guiding idea is calm. There is one hand-tuned light appearance, no settings to tune, and the interface stays quiet: the status bar says nothing when nothing is wrong, and speaks up — briefly and in plain terms — only when something needs your attention. It is built for engineers and power users who want a fast, predictable editor that gets out of the way.

els is built to never lose text you have saved: saves are atomic and durable, every overwrite keeps the file's previous version as a backup, and optional auto-save can write for you. It does not try to recover text you never saved — see Data safety.

Getting started

Download els.exe and run it. There is nothing to install and nothing to configure. On first launch you get one empty buffer and a tab strip.

  • Open a file — Ctrl+O, or drag a file onto the window, or File ▸ Open Recent.
  • New tab — Ctrl+N. Every file opens in its own tab.
  • Save — Ctrl+S (or Ctrl+Shift+S for Save As).
  • Make els your default editor — els writes nothing into the registry; use Windows' own mechanism, once per file type: right-click a file, Open with ▸ Choose another app, pick els (the first time, Choose an app on your PC and browse to els.exe — Windows remembers it afterwards), and tick Always. Help ▸ File Associations… walks through this and can remove the self-registration an older els may have left.

els remembers its window position and the set of open files between runs; a plain relaunch restores your last session. Launching els with a specific file (for example by double-clicking a document) opens just that file and leaves the saved session untouched until you next start els on its own.

Files & buffers

els distinguishes a file — the bytes on disk — from a buffer — the editable text held in a tab. Opening a file loads it into a buffer; saving writes the buffer back to a file. A buffer that has never been saved is untitled and has no file yet.

Each tab is one buffer. The tab shows the file's name and a dot when the buffer has unsaved edits. Closing a tab with unsaved edits asks whether to save first; the prompt spells out that No discards the changes and Cancel keeps the file open.

The status bar

The status bar runs along the bottom of the window. It follows one rule: no news is good news. Most of it is empty for a saved, unchanged file — it only shows what's worth knowing.

report.md             12:4LFUTF-8

From left to right:

Left — the file name

The active buffer's file path, shortened to fit (the filename always survives; leading folders are dropped behind a …\). Hover to see the full path and its length. This slot is also where brief, transient messages appear (a save that couldn't be written, a reload that failed) — for about four seconds, then the name returns.

Path-length badge

Just left of the name, a small red [N] badge appears only when the full path nears the Windows 260-character limit (from 200 characters up). Only the count is coloured; it is an early warning that a longer edit to this path may fail.

Disk state

Silent for a saved, unchanged file and for an untitled buffer. It shows a single terse word only for an exception:

ShowsColourMeaning
changedredThe file changed on disk since els last read it. Saving will ask before overwriting.
missingredThe file no longer exists at its saved path.
remotemutedA network path (UNC or a mapped drive). els doesn't poll it — nothing is wrong; its state is checked only on an explicit open, save, or reload.

Red means your file or your save is at risk; muted is for-your-information. Hover the word for a full explanation.

Position

12:4 — the caret's line and column (the compiler-error convention).

no auto-save

A muted no auto-save flag appears only when auto-save is on and it is paused for this buffer (the file changed on disk, or contains characters the target encoding can't hold). It stays visible until a manual save resolves it — so you're never falsely assured that auto-save has you covered. Hover for the specific reason.

Line endings & encoding (clickable)

The last two items — LF/CRLF and UTF-8 — are buttons (a hand cursor and hover highlight give them away). Click line endings to switch between LF and CRLF for saving. Click encoding to either reopen the file with a different charset or set the encoding used for the next save. See Encodings & line endings.

Update notice

If a newer els release is available, its version appears in red near the position readout; click it to open the download page. els checks once, quietly, at startup (set the environment variable ELS_NO_UPDATE_CHECK to skip it).

Find & replace

Open the find bar with Ctrl+F (or Ctrl+H to show the replace field). Enter jumps to the next match, Shift+Enter to the previous; F3 / Shift+F3 do the same without the bar focused. Esc closes it.

  • Real regular expressions — toggle .* in the find bar for full regex search and replace (with capture-group references in the replacement).
  • Case (Aa) and whole word (W) toggles.
  • Replace all operates on the whole buffer (or the selection). Large replacements are bounded and can be cancelled.
  • The ↑/↓ keys walk your recent search history.

Jump straight to a line with Ctrl+G (Go to Line).

Buffer transforms

The Buffer menu holds the built-in line operations, which act on the selected lines (or the current line):

CommandEffect
Move Line Up / DownShift the current line (or selection) by one row.
Duplicate LineCopy the current line below itself.
Delete Line · Join LinesRemove the line; or merge the next line onto this one.
Indent · DedentAdd or remove leading indentation. Tab indents when a selection spans lines.

Buffer scripts

Below the line operations, the Buffer menu lists your buffer scripts: plain Tcl files in a scripts folder next to els.conf, shown by file name. A script is a text filter — it receives the selection (or, with nothing selected, the whole buffer) in $text, along with $hasSelection, $path, and $lineCount, and whatever it returns replaces that text as a single undo step.

Scripts run in a sandbox: no file, program, or network access, and a hard time limit, so a script can at worst mangle text — and undo covers that. If a script fails, the buffer is left untouched and the status bar says so.

The classic transforms ship as editable default scripts — Sort Lines, Sort Lines Descending, Reverse Lines, Remove Duplicate Lines (first occurrence wins), UPPERCASE, lowercase, and Trim Trailing Whitespace. They double as worked examples of the contract: open one from the scripts folder to see the pattern. Delete any you don't want (the menu follows the folder after Reload Scripts); Restore Default Scripts rewrites the pristine set, leaving your own files alone; New Script… creates a file from the template and opens it for editing.

Data safety

els is built to protect text you have saved. The mechanisms are deliberately simple.

Atomic, durable saves

els never truncates the real file in place. It writes a complete temporary file alongside the target, then atomically replaces the target (preserving its security descriptor, alternate data streams such as the mark-of-the-web, and creation time), then flushes the bytes to the platter so a saved file survives power loss — not just a process crash. If the durability flush fails, the save is reported as failed and the tab stays marked unsaved, rather than pretending success.

An interrupted save can't corrupt your file. Because the new bytes are written to a temp file first and swapped in atomically, a crash or disk-full mid-save leaves the original intact; the complete new content is preserved in the temp and named in the error.

No silently lossy save

If the buffer contains characters the chosen encoding cannot represent faithfully, els will not quietly substitute them. It stops and offers to switch to UTF-8, substitute with your explicit consent, or cancel — so reopening a file never shows text you never wrote. See Encodings.

No recovery of unsaved text — by design

els keeps no crash-recovery snapshot of unsaved buffers. On a crash, forced reboot, or power loss, anything you had not saved (yourself or via auto-save) is gone — exactly as in a plain editor. What protects you instead is the atomic save, the previous-version backups, and optional auto-save. This is a considered trade for a minimal editor: snapshotting every keystroke to a sidecar, plus the locks and reconciliation dialogs that come with it, is more machinery and more failure surface than the promise is worth.

Auto-save

File ▸ Auto-save (off by default) writes buffers that have a filename through the normal atomic save as you work. It never invents a filename for an untitled buffer, and it pauses for a file that changed on disk or can't be encoded — surfacing the no auto-save flag until you save manually (see the status bar).

Backups

File ▸ Keep Backups (on by default) preserves the file's previous version every time you overwrite it — the primary safety net for edit-by-mistake. Backups live in a backups\ folder next to els's settings.

  • The folder is bounded, not an archive: a handful of versions per file, a burst of rapid saves keeps the version from before the burst, and copies age out after about a month.
  • Very large files are skipped (you get a one-time note when one is), and a backup that can't be written never blocks the save — you get a quiet status note and the save proceeds.
  • Restoring is low-tech: File ▸ Open Backups Folder, open the version you want (its name carries the original filename and a timestamp), and save it where it belongs.

Encodings & line endings

els auto-detects a file's character encoding on open (including BOM-marked UTF‑8/16/32 and common legacy code pages) and preserves it on save. The encoding and line-ending pills at the right of the status bar show the current values and are clickable.

Changing the encoding

Click the encoding pill (e.g. UTF-8) to either:

  • Reopen with a different charset — re-decode the file's bytes as another encoding (useful when auto-detection guessed wrong and you see replacement characters).
  • Set the encoding for the next save — convert the buffer to a different encoding when you save.

If a save would lose characters (they don't exist in the target encoding, or would round-trip to something different), els stops and asks — it never writes a silently lossy file. If a file was opened with the wrong encoding and shows replacement characters, els warns with lossy decode — try Reopen with Encoding.

Line endings

els detects the dominant line ending on open and shows LF, CRLF, or CR. Click the pill to switch what gets written on save. On save the whole buffer is normalised to the chosen ending.

External changes

When another program rewrites a file you have open — a build tool, git checkout, a formatter, or another editor — els notices and lights the changed disk indicator within a few seconds, whether or not els is the foreground window. If you then save, els performs an authoritative full check and asks before overwriting: save anyway, reload from disk, or cancel. A cancelled conflict leaves the indicator showing changed so you know it's unresolved.

File ▸ Reload from Disk re-reads the file, discarding your buffer edits (it asks first if the buffer is dirty).

Large files & network paths

An interactive open or reload asks before reading a file larger than about 40 MB — it may take a while and use a lot of memory — and flatly refuses one so large it would run out of memory and lose your other tabs. When a large file (or a file on a network path) turns up during quiet work such as a session restore, els doesn't read it eagerly; it opens a placeholder tab (marked with a ○) that loads when you click it — so startup never freezes or stalls on a share.

Very long lines — els won't open a file that contains a line longer than about 50,000 characters (minified JS/CSS/JSON, or a single-line data blob). A line that long freezes the text engine when you scroll, so els declines it with a clear message, just as it refuses a file too large to fit in memory.

Network paths — a UNC path or a mapped network drive is recognised as remote and shown as remote: els checks it only when you explicitly open, save, or reload, so a slow or disconnected share can never freeze the editor while you work on local files.

Restore Previous Session reopens the buffers from your last run; a large or network file among them comes back as a placeholder tab that loads on click.

Requirements & limitations

els runs on 64-bit Windows 10 (1903 or later) and Windows 11. It ships as one signed els.exe with no runtime dependencies.

Stated plainly so you know before you rely on it:

  • No screen-reader support. The underlying text engine is not exposed to Narrator/NVDA/JAWS; els is not usable with a screen reader today. This is an honest gap, not a setting.
  • No right-to-left text shaping. Arabic, Hebrew, and mixed-direction text display in logical, not visual, order.
  • Single, fixed appearance. One hand-tuned light palette (past WCAG AAA contrast); no configurable colours or fonts, no syntax highlighting, no minimap, and els does not follow the Windows dark-mode or High-Contrast theme.
  • One window per launch. els is single-instance-free: opening a file "with els" while it's running simply opens another window.

About

els is Dutch for awl, a small, sharp tool. It is a single-file Windows editor built on Tcl/Tk 9; the source and the build recipe are both public, so you can read it, fork it, or build it yourself. The About dialog acknowledges Tcl/Tk 9, MinGW-w64, and the ICU project.
